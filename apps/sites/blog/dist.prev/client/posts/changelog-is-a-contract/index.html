The changelog is a contract

Nobody reads changelogs until the upgrade breaks at 2am. Write them like the on-call engineer will.

craft

A changelog entry is a promise to a stranger: this is what will be different for you. Not a commit list, not a marketing line.

Write the entry for the person upgrading at 2am, not the person who wrote the code.

If a change needs a migration step, the entry says so first. Everything else is commentary.

Every word on this site was published through Colophon as release 5 of the demo-sites project, and this page names the release it was built from.
