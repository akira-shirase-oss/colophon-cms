# Decisions and deviations from the master spec

The master spec ([spec/](spec/README.md)) remains the reference design. This file records every place where Colophon
deliberately differs from it, plus decisions that are still open. Add an entry whenever a design changes: date,
decision, reason, impact.

| D-032 | 2026-10-25 | **Sessions are server-side rows; the cookie holds only a random token.** `colophon_session` carries 256 random bits (`HttpOnly; Secure; SameSite=Lax`); Postgres stores its SHA-256 hash. | D-033 | 2026-10-25 | **The database pool skips sqlx's ping on checkout, and a full pool answers 503.** `test_before_acquire(false)`; when no connection becomes free within the acquire timeout (2 s), the request gets 503 with `Retry-After: 1` (`DbError::Busy`, `ApiError::Busy`) and is logged at warn, never as an internal error. | The ping is a round trip on every checkout. | D-035 | 2026-10-25 | **Response shapes and write preconditions.** A resource is `{"data": …}`; a list is `{"data": [...], "next_cursor": …}`; the request id is in the `x-request-id` header, not the body. A missing `If-Match` or `Idempotency-Key` is 428; a malformed one, or `If-Match: *`, is 400; a stale `If-Match` is 409 with `details.reason` `stale_revision` and the current `ETag`. Saves need keys too, or a retry after a lost response (F02) would get a 409 from its own earlier save. Recording only successes means a failed attempt simply rolls back and can be retried. | The spec puts `request_id` and `revision` in success bodies; the header and `ETag` carry them instead. Projects and `/me` moved to this shape in step 1.2. Content hashes stay in the body as `content_hash`, and delivery ETags (P3) can be content hashes. |

| D-038 | 2026-10-25 | **The Studio's save model.** Edits are kept in this browser first (`localStorage`, per article, with the revision they build on), then saved a second after typing stops, one save at a time; every request times out after 15 s. A save keeps its `Idempotency-Key` while the base revision and content are unchanged, so a retry after a lost answer is replayed. A 409 opens the conflict screen with both versions: **Keep my version** saves mine on top of theirs (theirs stays in the history), **Use their version** discards my unsaved changes. Kept edits come back after a reload: on the current revision they are restored and saved, on an older one the conflict screen opens. The device copy also keeps a request that was in flight (base, key, content), and reopening sends exactly that again, so a save that committed before the page went away is replayed rather than stored twice (added in step 1.4, D-039). Kept edits expire after 30 days and are removed as soon as the server has them. | "Never lose an edit" has to cover a closed tab, a dropped network, an expired session and a server restart, not only a conflict; a device copy is the only thing that survives all four. The status line never says Saved before the server answers (ST1), and a conflict never drops the local edit without an explicit choice (ST2). | Differs from module 11 in two ways. The local copy is kept without asking for consent, because it is the person's own unsaved text in their own browser and is removed once saved; on a shared computer it lasts at most 30 days, and clearing it on sign-out comes with the Studio's sign-out control. Leaving the page only warns when the copy couldn't be kept, because otherwise nothing is lost and a prompt would add friction. Merging the two versions field by field is later; today the choice is per article. |
| D-039 | 2026-10-25 | **The simulator is hand-written and dependency-free** (closes O-011): `crates/colophon-sim` has a seeded `SplitMix64` generator, a single-threaded scheduler that picks every step from the seed, an in-memory model of the store, and editor actors that behave like the Studio's saver. Invariants are checked after every step and the run stops at the first failure, which `colophon-sim --seed N --trace` replays line for line. The model is kept honest by a differential test that replays runs against PostgreSQL; planted bugs (`--mutation`) must each be caught.
