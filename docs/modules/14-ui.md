## Why it exists

Three frontends drift apart quickly without shared tokens. Accessibility is also easier to get right once, in shared
components, than three times. The components are owned code (generated by the shadcn-svelte CLI and then restyled),
so the look is Colophon's and nothing upstream can change it without a reviewed diff.

## End goal

One token file and one library of owned components that every frontend uses, with light, dark and high-contrast
schemes, accessibility built in and tested, and a look of its own: quiet paper, black ink, one warm accent.

## Responsibilities

- Design tokens as CSS custom properties, mapped into Tailwind's theme (`src/lib/styles.css`).
- Owned Svelte components (`src/lib/components/ui/*`), exported as `@colophon/ui/ui/<name>`.
- Accessibility defaults: focus rings, contrast, reduced motion, target sizes.

## Not its job

- Page layouts. Each app owns its own navigation and layout (the Studio's shell lives in `apps/studio/src/lib/shell`).
- Content rendering ([content-renderer](12-content-renderer.md)).
- The public blog's visual identity. The blog may use these tokens, but its look is its own
  ([web-blog](15-web-blog.md)).

## Breakdown

### Colour

Warm off-white paper (`--background`), white sheets (`--card`, `--popover`) and near-black ink (`--foreground`,
`--primary`) in OKLCH, with hairline warm-grey rules (`--border`, `--input`). One accent, a burnt orange: `--brand` for
marks, charts and the glow (`.glow`: orange, peach and rose fields over paper; `.haze`: a faint warmth in a corner),
`--brand-ink` when it is text, `--brand-soft` as a ground. It is never body text or a button fill. States are plain,
each as three tokens (the mark, a soft ground for pills, an ink that reads on that ground):

| State | Colour | Meaning in the Studio |
|---|---|---|
| `live` | green | readers get it; verified |
| `pending` | amber | on its way: changed since live, awaiting review, delivery under way |
| `attention` | red | needs a person: stale, changes requested, failed, needs attention |
| `draft` | grey | not published, or in the CMS only |

Colour never carries a state alone: every pill has a word. Focus is an orange ring on an orange border. Five chart
colours lead with the accent. Dark mode is a warm near-black with white pills. Under `prefers-contrast: more` text,
inks and rules darken (or lighten, in dark mode) by themselves; there is no contrast setting to find.

### Type, shape, elevation, motion

One typeface, Inter, with its optical-size axis: large type uses Inter's display cut, set tight (`.display-1`,
`.display-2`, `.title`); figures are tabular (`.figure`, `.tabular`); small labels are `.eyebrow`. Mono (JetBrains Mono)
only for hashes, ids, addresses and code. Shape: pills for buttons, toggles, badges and segmented controls; 12px corners
for fields; 16 to 24px for menus, cards and dialogs. Elevation is hairline-and-haze, four shadows: `shadow-hairline`,
`shadow-soft` (cards, outline buttons), `shadow-float` (what floats over a page), `shadow-press` (filled buttons). Motion
is quick and purposeful and is cut to nothing under `prefers-reduced-motion`.

### Components

Every shadcn-svelte component (64 with Colophon's toolbar), generated by its CLI and owned here. The registry's "sera"
style is swept out (no uppercase, no wide tracking, no square corners, no underline-only fields), and the core set is
restyled by hand: button, badge (with `live`, `pending`, `attention`, `draft` and `brand` variants), input, textarea,
select, native select, input group, input OTP, checkbox, radio group, switch, slider, toggle, toggle group, button
group, tabs, card, alert, progress, calendar, menus and overlays. Grouped controls are one pill surface (button group,
toggle group and tabs alike). `cn` knows the custom shadows, so a caller's `shadow-none` replaces a component's
`shadow-soft`. Translucent text colours are not used, because the contrast test can only check tokens. Every component
is on one page: `/studio/design`.

## Invariants

| ID | Invariant |
|---|---|
| U1 | Every interactive component is keyboard-operable, labelled and visibly focused. |
| U2 | Motion respects the reader's reduced-motion setting. |
| U3 | Text uses token colours only, so every text colour is covered by the contrast test. |
| U4 | Every text colour meets WCAG AA on every ground it is drawn on, and AAA under more contrast. |
| U5 | The stylesheet and fonts load from the app's own origin; nothing from another. |

## Interfaces

- `@colophon/ui/styles.css`: the tokens, Tailwind and the fonts. An app imports it and adds
  `@source "<path to packages/ui/src>"`, because Tailwind doesn't scan dependencies.
- `@colophon/ui/ui/<component>` and `@colophon/ui/utils` (`cn` and prop helpers).

## Failure modes

| Situation | Behaviour |
|---|---|
| A token change weakens contrast | `packages/ui/test/tokens.test.ts` fails and names the pair |
| A component uses a colour that isn't a token | Caught by axe in the Studio's design tests (it was, once: an inactive tab at 60% opacity) |
| An upstream library (Bits UI, shadcn-svelte) changes | Versions are pinned and the components are copies, so updates are reviewed diffs |

## Tests and evidence

- `packages/ui/test/tokens.test.ts`: WCAG contrast computed from the OKLCH values (from first principles, not by the
  rendering library) for every text-on-ground pair, in light and dark at AA and in both under more contrast at AAA; the
  focus ring at 3:1; and no stylesheet loads from another origin.
- The Studio's design tests (`apps/studio/tests/design.spec.ts`): axe in light, dark and both contrast schemes, the
  toolbar's keyboard model, the theme choice surviving a reload, the contrast preference taking effect, focus returning
  from dialogs, and no requests to other origins.
- Screenshots of every Studio screen at desktop and phone widths, light and dark, for each design step.
