## Why it exists

Three frontends drift apart quickly without shared tokens. Accessibility is also easier to get right once, in shared
components, than three times. The components are owned code (generated by the shadcn-svelte CLI and then restyled),
so the look is Colophon's and nothing upstream can change it without a reviewed diff.

## End goal

One token file and one library of owned components that every frontend uses, with light, dark and high-contrast
schemes, accessibility built in and tested, and a look of its own: a printed page, quiet until something needs saying.

## Responsibilities

- Design tokens as CSS custom properties, mapped into Tailwind's theme (`src/lib/styles.css`).
- Owned Svelte components (`src/lib/components/ui/*`), exported as `@colophon/ui/ui/<name>`.
- Accessibility defaults: focus rings, contrast, reduced motion, target sizes.

## Not its job

- Page layouts. Each app owns its own navigation and layout (the Studio's shell lives in `apps/studio/src/lib/shell`).
- Content rendering ([content-renderer](12-content-renderer.md)).
- The public blog's visual identity. The blog may use these tokens, but its look is its own
  ([web-blog](15-web-blog.md)).

## Breakdown

### Colour

Warm paper (`--background`, `--card`) and blue-black ink (`--foreground`, `--primary`) in OKLCH; the sidebar is a warmer
grey frame around the white page. States take printer's registration colours, each as three tokens: the mark (a dot or
an icon), a soft ground for pills, and an ink that reads on that ground:

| State | Meaning in the Studio |
|---|---|
| `live` | readers get it; verified |
| `pending` | on its way: changed since live, awaiting review, delivery under way |
| `attention` | needs a person: stale, changes requested, failed, needs attention |
| `draft` | not published, or in the CMS only |

Colour never carries a state alone: every pill has a word. `--proof` (a red) marks the brand and links in prose; focus is
a blue ring (`--ring`), because red on a field reads as an error. Dark mode is a darkroom: warm near-black, paper-coloured
type. Under `prefers-contrast: more` text, inks and rules darken (or lighten, in dark mode) by themselves; there is no
contrast setting to find.

### Type, shape, motion

One typeface, Inter (variable, self-hosted). Mono (JetBrains Mono) only for hashes, ids, addresses and code. Radius
0.625rem for controls, larger for cards and dialogs, a large rounded corner on the page panel. Motion is quick and
purposeful (a page settles in, rows arrive in sequence, the theme spreads from its button as a view transition) and is
cut to nothing under `prefers-reduced-motion`.

### Components

Alert, avatar, badge (with the four state variants), breadcrumb, button, card, checkbox, command (the palette), dialog,
dropdown menu, input, input group, label, popover, scroll area, select, separator, sheet, sidebar, skeleton, sonner
(toasts), table, tabs, textarea, toolbar (one tab stop with roving arrow keys, for the rich-text toolbar) and tooltip.
Restyled from the generator's "Sera" preset: no forced uppercase or letter-spacing, rounded controls, boxed fields.
Translucent text colours are not used, because the contrast test can only check tokens.

## Invariants

| ID | Invariant |
|---|---|
| U1 | Every interactive component is keyboard-operable, labelled and visibly focused. |
| U2 | Motion respects the reader's reduced-motion setting. |
| U3 | Text uses token colours only, so every text colour is covered by the contrast test. |
| U4 | Every text colour meets WCAG AA on every ground it is drawn on, and AAA under more contrast. |
| U5 | The stylesheet and fonts load from the app's own origin; nothing from another. |

## Interfaces

- `@colophon/ui/styles.css`: the tokens, Tailwind and the fonts. An app imports it and adds
  `@source "<path to packages/ui/src>"`, because Tailwind doesn't scan dependencies.
- `@colophon/ui/ui/<component>` and `@colophon/ui/utils` (`cn` and prop helpers).

## Failure modes

| Situation | Behaviour |
|---|---|
| A token change weakens contrast | `packages/ui/test/tokens.test.ts` fails and names the pair |
| A component uses a colour that isn't a token | Caught by axe in the Studio's design tests (it was, once: an inactive tab at 60% opacity) |
| An upstream library (Bits UI, shadcn-svelte) changes | Versions are pinned and the components are copies, so updates are reviewed diffs |

## Tests and evidence

- `packages/ui/test/tokens.test.ts`: WCAG contrast computed from the OKLCH values (from first principles, not by the
  rendering library) for every text-on-ground pair, in light and dark at AA and in both under more contrast at AAA; the
  focus ring at 3:1; and no stylesheet loads from another origin.
- The Studio's design tests (`apps/studio/tests/design.spec.ts`): axe in light, dark and both contrast schemes, the
  toolbar's keyboard model, the theme choice surviving a reload, the contrast preference taking effect, focus returning
  from dialogs, and no requests to other origins.
- Screenshots of every Studio screen at desktop and phone widths, light and dark, for each design step.
