# 13 · sdk (`packages/sdk`)

> A TypeScript client — its types generated from the served OpenAPI document — with generation-pinned reads, so
> websites can read content consistently across one release.

| | |
|---|---|
| Milestones | P2 (generated client, pinned-read helper), P3 (used by the blog and Studio) |

| Depends on | the OpenAPI document exported by [api](04-api.md) |

## Why it exists

A website often makes several related reads to build one page: a post, its author, its category. If a release lands
between those reads, the page mixes two releases. The SDK pins one `(epoch, generation)` across related reads, and it
removes hand-written API code that would drift from the server.

## Current state

Built in DX.8 (D-112): `@colophon-cms/sdk`, versioned `0.1.0-alpha.7` with the server.

- **Types** are generated by `openapi-typescript@7.13.0` from `docs/api/openapi.json` into the checked-in
  `src/api.types.ts` (`--empty-objects-unknown`, so the document's bare `type: object` schemas —
  `EntryDocument`, `QueryDocument`, `TypeDefinition` — land as `Record<string, unknown>`). `npm run gen`
  rewrites it through the generator's programmatic API; `npm run check` byte-compares it, the same
  no-drift rule the document's own artifact test enforces.
- **The client** is hand-written: `new Client({ baseUrl, token })`, `client.environment(project)` for
  the `{P}` content surface, `client.delivery(project)` for `/content/v1`. Methods carry the generated
  types verbatim — request bodies are the document's schemas, replies are the wire shapes plus a
  `response` of `{status, etag, replayed, requestId, generation}` — and required route guards are required
  parameters: `idempotencyKey` on every write, `ifMatch` wherever the route reads `If-Match`. Coverage
  is the core third of the operations (entries and their bounded query, content types, changesets and
  reviews, releases and receipts, comments and tasks, migrations read-only, assets list, health,
  version, identity, permissions); the rest stays reachable through the exported `paths`/`operations`
  types.
- **Errors** arrive as `ApiError`: status, the envelope's `code`/`message`/`request_id`/`details`
  (refusal `reason` + JSON `pointer`), the conflict's current `etag`, `retryAfterMs` and a `retryable`
  flag true only when nothing was written.
- **No second auth surface:** the client attaches a bearer token or a session descriptor
  (`{csrf, cookie?}`); it never signs in, refreshes or stores a credential.
- **Pinned reads:** `client.delivery(p).atGeneration(g)` returns a scope whose reads all name `g`;
  asking for a different generation on it throws. Every reply's `response.generation` is the
  `Colophon-Generation` it answered from (`null` where a route sends none), so a page pins the
  generation of its first read.
- **Bounds:** `timeoutMs` (15 s default, joined with the caller's `signal`) and `maxBodyBytes`
  (16 MiB default) on every call.
- **Server-version check (D-170):** `client.compatibility()` reads `/version` and applies the CLI's
  rule (`crates/colophon-cli/src/compat.rs`, D-062) — the API version, then before 1.0 the minor
  line, then `OLDEST_SERVER` — answering `{compatible, sdk, server, api, misfit?, reason?}`, where
  `reason` says which side to upgrade and to what. The client runs it once, lazily, before its
  first API call: `compat: 'warn'` (default) logs the reason beside the call and never delays or
  fails it; `'throw'` fails every call with `incompatible_server` (not retryable) and sends
  nothing; `'off'` never asks. A check with no answer decides nothing and is asked again on the
  next call; `livez`, `readyz` and `version` never wait on it. `SDK_VERSION` is the workspace
  version, tested against `package.json` and `Cargo.toml`.
- **Packaging (D-170):** ESM only, no runtime dependencies, `types` and `exports["./package.json"]`,
  `publishConfig.provenance`. `scripts/pack-check.mjs` (run by `scripts/frontend.sh`, so by CI's
  frontend job) packs this package and `@colophon-cms/rich-text` and checks the tarballs, not the
  tree: a file allowlist (`dist/` `.js`/`.d.ts`, README, LICENSE, CHANGELOG, `package.json`) and
  size budget (150 KB packed; rich-text 20 KB), the workspace version, no dependencies (so never a
  private `@colophon/*` name), `publint --strict`, Are the Types Wrong (`esm-only`), then a scratch
  project with only the tarballs installed: a Node ESM script against a stub server (livez, the
  compatibility check, a delivery read rendered), the README's read-and-render example run as
  written against the stub (its second read must carry the first's generation), every rich-text
  fixture against its reviewed HTML, a type-check of a consumer file and of every `ts` block in both READMEs under `nodenext`
  and `bundler` resolution with TypeScript 5.9 and 6.0, and a browser bundle of `Client` and
  `Delivery` held to 12 KB min+gzip (4.5 KB at 0.1.0-alpha.1). Last, each package's public API —
  every export of the packed `dist/index.d.ts`, declarations as written, generated wire types by
  name only — must equal its committed `api-report.txt` (`scripts/api-report.mjs … --update`
  rewrites it), so a removed, renamed or re-typed export shows up in review.
- **Rich text outside the monorepo (D-170):** `@colophon-cms/rich-text` (`packages/rich-text`) is
  the content renderer as a zero-dependency package: its build assembles
  `packages/content-renderer/src/render.ts` and `packages/editor/src/schema.ts` (plus the stored
  format's types from `stored.ts`) and compiles them, so it can't drift from the Studio's preview;
  its tests and the pack check render every fixture from the built and the packed code.
- **Images:** `mediaFor(row[, { current, sizes }])` turns a delivery row's `media` sidecar — every
  asset its published revision names, at the version its release recorded
  ([06](06-delivery.md), [07](07-media.md)) — into the rich-text renderer's `media` option
  (renderer v2, [12](12-content-renderer.md)): the immutable versioned source, `width`/`height`,
  and the `wN` renditions as `srcset` width candidates with a default `sizes`. `{ current: true }`
  follows `current_url` instead: the newest published version. An id the sidecar doesn't hold answers
  `undefined`, so the renderer falls back to its bare address. The sidecar's type is the
  generated `PublishedMedia`.

- **Draft preview on a customer's site** (D-171, D-172, D-181; `src/preview.ts`, framework-agnostic on the Web
  `Request`/`Response` types): `previewClient({baseUrl, project, environment})` → `.exchange(code)` and
  `.reader(token)` with `list`, `get`, `query` and `session` over `/preview/v1` (bearer, `ApiError` keeping the
  refusal's `reason`); `createPreviewHandler` (validates `?path=` as a same-site relative path — no open redirect
  — exchanges the code, keeps the token in an `HttpOnly; Secure; SameSite=None; Partitioned` cookie and answers
  `303` with `no-store`, `no-referrer`, `noindex`); `previewTokenFromRequest`; `previewHeaders({studioOrigin})`
  (`private, no-store`, `noindex`, `frame-ancestors <studio>`) for every preview-mode page; `exitPreviewHandler`;
  and the browser's `listenForDraftUpdates({studioOrigin, previewing})`, which sends the Studio's
  `colophon:preview-ready` handshake and reloads on `colophon:draft-saved` from exactly the Studio's origin.
  The testbed's `/preview/{project}/…` pages are the SvelteKit example (`docs/guides/preview.md` adds Astro and
  Next.js); its spec puts a caching proxy in front of the site and proves a preview page is never stored or
  served to an anonymous reader.

Still to come from the end goal: adoption by the blog/Studio, and the epoch half of the pin — the
delivery API reads `?generation=` today; pinning `(epoch, generation)` waits on the wire naming
epochs. Spec §10's deprecation window for contract changes applies when the SDK ships publicly.

## Responsibilities

- Generated types and calls.
- The pinned-read helper.
- Idempotent retries.
- Typed errors.
- Versioning in step with the API.

## Not its job

- Business rules or validation authority.
- Caching policy, which belongs to [delivery](06-delivery.md).
- Signing in: a credential is given to the client, never minted by it (one API, no bypass).

## Breakdown

- **Generated types:** `src/api.types.ts` from `openapi-typescript`, checked in and drift-checked in
  CI (`npm run gen` regenerates; `npm run check` compares).
- **Hand-written client:** one `fetch` loop under typed method names — the envelope, the ETag and
  Idempotency-Key discipline, the bounded read and the pinned scope are reviewed code, not
  generator output.
- **Pinned reads:** `delivery(project).atGeneration(g)` resolves the generation once and reads
  everything at it.
- **Mutations:**
  - every write carries one idempotency key, supplied by the caller so its retries reuse it;
  - updates send `If-Match` (the resource's `ETag`, surfaced as `response.etag`);
  - errors are typed from the error envelope (`code`, `details`, `request_id`).
- **Versioning:** the SDK is versioned with the API (`0.1.0-alpha.7`), with a documented deprecation
  window for contract changes (spec §10).

## Invariants

| ID | Invariant |
|---|---|
| K1 | Reads made through one pinned scope always use one `(epoch, generation)`. |
| K2 | A retried mutation reuses its idempotency key. |

## Interfaces

- `new Client({ baseUrl, token | session, fetch?, headers?, timeoutMs?, maxBodyBytes? })`,
  `client.environment(project[, environment])`, `client.delivery(project[, environment])` and
  `.atGeneration(g)`, `newIdempotencyKey()`.
- `mediaFor(row, options?)`, `imageSource(media, options?)`, `DEFAULT_SIZES`, and the
  `PublishedMedia`/`MediaSidecar`/`ImageSource` types.
- `ApiError` with `status`, `code`, `details`, `reason`, `pointer`, `etag`, `retryAfterMs`,
  `retryable`.
- `client.compatibility()`, `ClientOptions.compat` (`'off' | 'warn' | 'throw'`), `SDK_VERSION`.
- `@colophon-cms/rich-text`: `renderToHtml(value, { assetUrl })`, `UnrenderableContent`,
  `RENDERER_VERSION`, `RICH_TEXT_SCHEMA`, `RICH_TEXT_VERSION`, the stored-format types.

## Failure modes

| Situation | Behaviour |
|---|---|
| Pinned generation becomes unavailable (revoked content) | Typed error; the page decides what to show; no silent fallback to another release |
| Transient failure on a mutation | Retry with the same key, within the caller's deadline — the client never retries silently |
| Answer over the byte cap or not JSON | `response_too_large` / `invalid_response` `ApiError`, status kept |
| No answer | `no_answer` `ApiError`, status 0, retryable |
| Server too old or too new for this SDK | `warn`: one `console.warn` naming which side to upgrade; `throw`: `incompatible_server`, nothing sent |
| Server without `/version` | Treated as older than every supported server (`no_version_report`) |

## Tests and evidence

- Mocked-fetch contract tests per method group (what is sent; envelope, ETag, idempotency and
  refusal handling on the way back) plus type-level tests in `packages/sdk/test/` — `tsc` is the
  proof for half of them.
- `test/media.test.ts`: `mediaFor` — released and current sources, candidates narrowest first,
  narrow uploads without a `srcset`, unknown and inherited ids falling back.
- A real-server suite gated on `COLOPHON_TEST_ORIGIN` (the `#[ignore]` equivalent): version,
  livez, a typed 401, the served document.
- The compatibility table from `compat.rs`, SemVer precedence, and the client's lazy check in each
  mode (`test/compat.test.ts`).
- The packaging gate above, on every push; README examples compile in CI from the packed tarballs.
- Load (D-018's equivalent for a client): `perf/node/sdk-delivery.mjs` drives delivery `list`/`get`
  calls through the packed SDK and the same requests through bare `fetch`, against a stub in its own
  process or a real server (`ORIGIN`, `PROJECT`, `COLLECTION`, `ENTRY`), and records the client's
  p50/p99 overhead (budget: p99 within 1 ms of bare fetch) and heap growth once every call's
  15-second deadline timer has fired (budget 20 MB). `scripts/frontend.sh` runs a 20,000-call smoke
  that gates failed calls and heap growth and records the overhead without gating it
  (`OVERHEAD_GATE=record`): on a shared machine the gap between two tails measures the machine's load,
  not the client. On 2026-11-17 a smoke on a busy laptop had 0 failures and no heap growth (−0.6 MB)
  while its overhead swung from −0.9 to +11.5 ms between runs, and on 2026-11-21 the same code's p99
  overhead was 25.05 ms at a load average near 50 and 0.38 ms near 20, which failed QUICK on the
  loosened 25 ms bound it then had. The full 1,000,000-call run, on a quiet machine or the evidence
  runner, gates all three; it is owed.
- The packed packages against the real server (`apps/testbed/tests/sdk.spec.ts`, D-170): a person
  publishes in the browser; the SDK and rich-text tarballs, installed in a scratch project, check
  the server's version (`compat: 'throw'`), read the release anonymously, render its body, and pin
  a page to generation 1 while generation 2 lands between its reads — the pinned list and get stay
  at 1 (K1), the latest moves to 2.
