# 13 · sdk (`packages/sdk`)

> A TypeScript client — its types generated from the served OpenAPI document — with generation-pinned reads, so
> websites can read content consistently across one release.

|---|---|
| Milestones | P2 (generated client, pinned-read helper), P3 (used by the blog and Studio) |

## Why it exists

A website often makes several related reads to build one page: a post, its author, its category. If a release lands
between those reads, the page mixes two releases. The SDK pins one `(epoch, generation)` across related reads, and it
removes hand-written API code that would drift from the server.

## Current state

Built in DX.8 (D-112): `@colophon-cms/sdk`, versioned `0.1.0-alpha.1` with the server.

- **Types** are generated by `openapi-typescript@7.13.0` from `docs/api/openapi.json` into the checked-in
  `src/api.types.ts` (`--empty-objects-unknown`, so the document's bare `type: object` schemas —
  `EntryDocument`, `QueryDocument`, `TypeDefinition` — land as `Record<string, unknown>`). `npm run gen`
  rewrites it through the generator's programmatic API; `npm run check` byte-compares it, the same
  no-drift rule the document's own artifact test enforces.
- **The client** is hand-written: `new Client({ baseUrl, token })`, `client.environment(project)` for
  the `{P}` content surface, `client.delivery(project)` for `/content/v1`. Methods carry the generated
  types verbatim — request bodies are the document's schemas, replies are the wire shapes plus a
  `response` of `{status, etag, replayed, requestId}` — and required route guards are required
  parameters: `idempotencyKey` on every write, `ifMatch` wherever the route reads `If-Match`. Coverage
  is the core third of the operations (entries and their bounded query, content types, changesets and
  reviews, releases and receipts, comments and tasks, migrations read-only, assets list, health,
  version, identity, permissions); the rest stays reachable through the exported `paths`/`operations`
  types.
- **Errors** arrive as `ApiError`: status, the envelope's `code`/`message`/`request_id`/`details`
  (refusal `reason` + JSON `pointer`), the conflict's current `etag`, `retryAfterMs` and a `retryable`
  flag true only when nothing was written.
- **No second auth surface:** the client attaches a bearer token or a session descriptor
  (`{csrf, cookie?}`); it never signs in, refreshes or stores a credential.
- **Pinned reads:** `client.delivery(p).atGeneration(g)` returns a scope whose reads all name `g`;
  asking for a different generation on it throws.
- **Bounds:** `timeoutMs` (15 s default, joined with the caller's `signal`) and `maxBodyBytes`
  (16 MiB default) on every call.

Still to come from the end goal: adoption by the blog/Studio, and the epoch half of the pin — the
delivery API reads `?generation=` today; pinning `(epoch, generation)` waits on the wire naming
epochs. Spec §10's deprecation window for contract changes applies when the SDK ships publicly.

## Responsibilities

- Generated types and calls.
- The pinned-read helper.
- Idempotent retries.
- Typed errors.
- Versioning in step with the API.

## Not its job

- Business rules or validation authority.
- Caching policy, which belongs to [delivery](06-delivery.md).
- Signing in: a credential is given to the client, never minted by it (one API, no bypass).

## Breakdown

- **Generated types:** `src/api.types.ts` from `openapi-typescript`, checked in and drift-checked in
  CI (`npm run gen` regenerates; `npm run check` compares).
- **Hand-written client:** one `fetch` loop under typed method names — the envelope, the ETag and
  Idempotency-Key discipline, the bounded read and the pinned scope are reviewed code, not
  generator output.
- **Pinned reads:** `delivery(project).atGeneration(g)` resolves the generation once and reads
  everything at it.
- **Mutations:**
  - every write carries one idempotency key, supplied by the caller so its retries reuse it;
  - updates send `If-Match` (the resource's `ETag`, surfaced as `response.etag`);
  - errors are typed from the error envelope (`code`, `details`, `request_id`).
- **Versioning:** the SDK is versioned with the API (`0.1.0-alpha.1`), with a documented deprecation
  window for contract changes (spec §10).

## Invariants

| ID | Invariant |
|---|---|
| K1 | Reads made through one pinned scope always use one `(epoch, generation)`. |
| K2 | A retried mutation reuses its idempotency key. |

## Interfaces

- `new Client({ baseUrl, token | session, fetch?, headers?, timeoutMs?, maxBodyBytes? })`,
  `client.environment(project[, environment])`, `client.delivery(project[, environment])` and
  `.atGeneration(g)`, `newIdempotencyKey()`.
- `ApiError` with `status`, `code`, `details`, `reason`, `pointer`, `etag`, `retryAfterMs`,
  `retryable`.

## Failure modes

| Situation | Behaviour |
|---|---|
| Pinned generation becomes unavailable (revoked content) | Typed error; the page decides what to show; no silent fallback to another release |
| Transient failure on a mutation | Retry with the same key, within the caller's deadline — the client never retries silently |
| Answer over the byte cap or not JSON | `response_too_large` / `invalid_response` `ApiError`, status kept |
| No answer | `no_answer` `ApiError`, status 0, retryable |
