# F08 evidence: Cache eviction/failover/restart

Required invariant (module 17): No loss of content, jobs, sessions or hard budget accounting.

Valkey holds only delivery-cache answers and limiter counts; content, jobs, releases, sessions and hard budgets are Postgres's.
- Eviction: `crates/colophon-server/tests/cache.rs` `a_flushed_or_full_cache_loses_answers_never_content`: `FLUSHALL`, then the memory cap set just above what Valkey holds (`allkeys-lru`, as every install sets it; restored to 128 MB after): over 100 pages and 30 entry reads every answer is the release's, `evicted_keys` rises. `answers_survive_valkey_going_away_and_caching_resumes_when_it_is_back`: Valkey stopped, answers bypass the cache, a release shows at once, caching resumes.
- Sessions: `a_session_outlives_valkey_stopping_starting_and_flushing`.
- Jobs: `purges.rs` `a_release_published_while_valkey_is_down_is_delivered_once`: its purge accepted once, never repeated once Valkey is back.
- Budget accounting, named: hard budgets (`documents_per_day`, `max_concurrent_jobs`) are Postgres counts and never fall back: `budgets.rs` `a_documents_budget_counts_the_same_with_valkey_down_restarted_or_flushed`. The rate limits (D-076) and the token request quota (D-118) fall back to a count per server while Valkey is down, limited and never unlimited: `admission.rs` `without_valkey_each_server_still_limits_on_its_own`, `quotas.rs` `without_valkey_a_token_is_still_limited_never_unlimited`; the local maps are bounded against a flood of keys by D-238.
- Failover: `scripts/failover.sh kill` and `drain` (D-075) under write load through HAProxy, 3 servers and 2 workers: every acknowledged write stored exactly once.

Machine: apple-m2-pro-12c (12 cores, macOS). Stack: `COMPOSE_PROJECT_NAME=colophon-verify` with `COLOPHON_PG_PORT=58220 COLOPHON_VALKEY_PORT=58221 COLOPHON_S3_PORT=58222 COLOPHON_S3_ADMIN_PORT=58223`, brought up with `scripts/stack.sh up && scripts/migrate.sh` for the run and taken down after (D-187c); tests with `COLOPHON_TEST_ORIGIN=http://localhost:58238`.
